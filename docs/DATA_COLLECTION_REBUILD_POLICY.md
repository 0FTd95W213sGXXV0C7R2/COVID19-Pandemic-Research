# データ収集・再構築の統一方針

- 決定日：2026-11-19
- 記録日時（日本時間）：2026/11/19 13:48:53
- 対象：本研究の全データ収集（疫学指標、医療資源、救急搬送、患者・家族、医療従事者、政策・運用、倫理問題の直接証拠を含む）
- 正本：本ファイル。以後の個別データセット・取得監査は本方針に従う。

## 1. 決定

**今後のデータ収集は、既存のCSV・加工済みデータ・過去の抽出結果をそのまま引き継がず、原則として出典の原資料から新規に取得し、取得・検証・整形・登録を一から再構築する。**

この方針は消防庁の救急搬送困難事案だけでなく、本研究で今後収集するすべてのデータに適用する。ユーザーが明示的に例外を承認しない限り、過去に作成されたデータファイル、集計値、派生CSV、スクレイピング結果、分析用データを新しい正本データに流用しない。

既存のNotion記録、参考文献DB、GitHub文書、既存監査記録は、出典候補・方法上の注意・過去の判断・再調査対象を把握するための**参考情報**として参照してよい。ただし、過去の数値・加工データを新規取得済みデータとして扱わない。原資料から再取得できない場合は、取得不能・未検証と明記し、過去の値で穴埋めしない。

## 2. 収集標準ワークフロー

1. **出典確定**：一次資料・公式公開資料を優先し、出典URL、発行主体、資料名、公開日、対象期間、取得日（JST）を記録する。
2. **原資料取得**：可能な限り公式配布元から原ファイルを直接取得する。APIの場合はエンドポイント、パラメータ、取得日時を保存する。ミラー・二次配布は公式原資料を取得できない場合の代替とし、代替利用であることを明示する。
3. **原本保全**：利用規約・著作権・個人情報・機密性を確認する。保存可能な場合のみ原本を保全し、SHA-256、ファイルサイズ、形式、取得元を記録する。保存不可の場合は、URL、取得日時、HTTP/API応答情報、取得コード等、許される監査情報を残す。
4. **新規変換**：変換コードを新規作成し、手作業による値の転記を避ける。変換前後の行数、列名、型、単位、日付範囲、重複、欠測、ゼロ、外れ値、集計整合性を検査する。
5. **定義・系列監査**：対象範囲、分母、地理単位、施設・人口範囲、時間粒度、定義変更、速報・確報、改訂、集計方法、対象施設変更を確認する。異なる定義の系列を無条件に接続しない。週次・月次を日次に補間しない。
6. **再現可能な登録**：原本（保存可能な場合）、取得スクリプト、変換スクリプト、検証コード、データ辞書、監査報告、出典メタデータをGitHubに登録する。実データの登録は利用条件・容量・機密性を確認したうえで行う。
7. **独立検証**：行数・期間・集計値・ハッシュ等を再確認し、テスト結果を記録する。検証が終わるまで「確定」「採用済み」と表記しない。
8. **記録**：研究判断・進捗・未解決事項はNotionに日本時間の記録日時付きで記録し、GitHubの該当ファイル・コミットと相互参照する。

## 3. GitHubの成果物標準

データセットごとに、原則として次を作成する（不要な項目は理由を記録して省略可能）。

- `data/raw/<dataset>/`：利用条件上保存可能な原資料
- `data/processed/<dataset>/`：検証済み加工データ
- `src/collect/<dataset>/`：取得コード
- `src/transform/<dataset>/`：変換・整形コード
- `tests/<dataset>/`：品質検査
- `audit/<dataset>/` または `docs/audits/`：取得・品質・定義監査
- `data/metadata/<dataset>/manifest.json`：取得元、取得日時、ファイル名、SHA-256、サイズ、期間、粒度、定義、処理コードの版、検査結果
- データ辞書：列名、意味、型、単位、分母、欠測表現、対象範囲、制約

各データセットに固有のIDを付与し、出典ID・原資料ハッシュ・取得コード版・変換コード版・生成物ハッシュを追跡できるようにする。取得と変換を再実行できる手順をREADMEに記載する。

## 4. 既存データ・既存記録の扱い

- 既存ファイルは無断で削除・上書きしない。
- 過去データは履歴・比較・監査対象として残し、新規構築データと明確に区別する。
- 新規構築データが検証完了した時点で、どの既存ファイルを置き換えるか、または併存させるかを記録する。
- 旧データの値を新データの欠測補完や検証の正解値として使わない。比較する場合は独立した参考比較として明記する。
- 公式原資料を再取得できない場合、過去の取得物を無断で正本化せず、ユーザーに必要なファイル提供を依頼するか、取得不能として保留する。

## 5. 品質・研究上の原則

- 倫理的問題の直接証拠、疫学・医療負荷の背景指標、政策・運用、倫理規範を分離する。
- データが示す関連、時間的併存、因果関係を区別する。
- 集計単位・対象範囲・時間粒度が異なるデータを安易に比較しない。
- 欠測とゼロを区別し、推測で補完しない。
- 定義変更・測定方法変更・対象範囲変更をデータ辞書と監査記録に残す。
- 公開資料のみを対象とし、研究者・施設への直接照会を前提としない。
- 個人情報・機密情報・利用条件に反するデータを取得・登録しない。

## 6. 直近の適用対象：消防庁・救急搬送困難事案

既存のCode for FUKUIミラーCSV（162週、全体系列）は、今回の監査で構造・合計整合性を確認したが、**新規構築データの正本には採用しない**。消防庁公式Excelの原資料から取得・解析し直す。公式Excelには既存Notion記録上、全体（今回）、全体（前年同期）、COVID疑い（今回）、非COVID疑い（今回）の4シートが記録されているが、これらの週範囲・年度境界・欠測・ゼロ・速報確報・対象消防本部の変化を原本から再監査する。公式原資料をこの環境で取得できない場合は、ユーザーが提供した原本を使用するまで確定を保留する。

## 7. 変更管理

この方針を変更する場合は、ユーザーの明示的な指示を必要とする。例外を認める場合は、対象データセット、再利用する過去成果物、理由、影響範囲、独立検証方法を記録する。
